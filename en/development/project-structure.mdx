The repository is a pnpm workspace: `apps/` holds the desktop and mobile apps, `packages/` holds the first-party plugins, and `crates/` pulls in native dependencies such as the Electron runtime as submodules.

```text
deepseek-harness-desktop/
├── apps/
│   ├── desktop/            # Desktop app
│   │   ├── src/            # React frontend (Vite + Tailwind CSS 4)
│   │   └── src-tauri/
│   │       ├── src/
│   │       │   ├── bridge/     # Tauri command boundary
│   │       │   ├── config/     # Paths, constants, and settings
│   │       │   ├── desktop/    # Windows, menus, and OS integration
│   │       │   ├── service/    # Runtime and desktop services
│   │       │   └── task/       # Periodic task entry points
│   │       ├── resources/      # Runtime manifest and bundled plugin outputs
│   │       ├── vendor/         # Patched native dependencies
│   │       └── tauri.conf.json
│   └── native/             # Expo / React Native mobile app
├── packages/
│   ├── builtin-plugin-*/   # First-party plugin sources; builds land in desktop resources
│   └── builtin-plugin-config/  # Shared configuration and types
├── crates/                 # Submodules: electron-rs, tauri-runtime-electron, notification plugin
├── scripts/                # Plugin build, maintenance, and release scripts
├── config/                 # Vitest project configuration
├── tests/                  # Unit tests and desktop E2E
├── docs/                   # In-repository engineering notes
└── .github/workflows/      # CI and release pipelines
```

## Frontend

`apps/desktop/src/` contains components, configuration, hooks, internationalization, layouts, stores, styles, and utilities. It renders installation and loading states, desktop settings, and UI surrounding the embedded Harness client.

## Native backend

The `apps/desktop/src-tauri/src/service/` modules are organized around capabilities such as downloads, core selection, profiles, plugins, CLI integration, updates, workflows, and scheduling. `bridge/` exposes selected capabilities as Tauri commands; UI code should not bypass that boundary. Windows and the event loop run inside Electron through `crates/tauri-runtime-electron`, while Rust keeps commands, CSP, and ACL.

## First-party plugins

Each `packages/builtin-plugin-*` directory is its own package; `pnpm build:plugins` deploys them into `apps/desktop/src-tauri/resources/node_modules` at build time. The `plugins.built-in` list in `resources/manifest.jsonc` decides which IDs ship with the app, and plugin sources are no longer hosted in a separate repository.

## Where to make a change

| Change | Start here |
| --- | --- |
| React view or state | `apps/desktop/src/` |
| First-party plugins | `packages/builtin-plugin-*/` |
| Native command contract | `apps/desktop/src-tauri/src/bridge/` |
| Paths or persisted settings | `apps/desktop/src-tauri/src/config/` |
| Window, menu, or OS integration | `apps/desktop/src-tauri/src/desktop/` |
| Core, profile, plugin, CLI, or update behavior | `apps/desktop/src-tauri/src/service/` |
| Startup, restart, and process orchestration | `apps/desktop/src-tauri/src/service/workflow/` |
| Periodic status checks | `apps/desktop/src-tauri/src/task/` |
| Mobile app | `apps/native/` |
| CI or packaging | `.github/workflows/`, [Tauri configuration](https://github.com/dsh-tauri/deepseek-harness-desktop/blob/main/apps/desktop/src-tauri/tauri.conf.json) |

Keep operating-system differences behind focused Rust services and preserve the release
and debug isolation model when adding paths, ports, or stores.
