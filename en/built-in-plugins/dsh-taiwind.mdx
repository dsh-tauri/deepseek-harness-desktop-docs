title: DSH Taiwind
description: Understand the shared Tailwind stylesheet plugin shipped with the desktop resources and what it requires from plugin authors.
---

`dsh-taiwind` is a shared styling plugin listed under the manifest's `plugins.built-in`. It collects the Tailwind utility classes used by client plugins on the host side and compiles them into a single stylesheet injected into the page. It has no interface and no tools; its only output is the shared style endpoint `plugins/taiwind.css` and a `<style data-plugin="dsh-taiwind">` element.

## Why it ships with the desktop

- When each plugin publishes on its own, the same `flex`, `gap-2`, and `w-full` get compiled and loaded several times on one page.
- Moving the compile step into the host process lets plugins stay independently published and built, without one monorepo and without per-plugin deduplication.
- Built-in plugins and optional presets rely on this shared stylesheet, so it ships with the installer instead of asking users to install it separately.

## What plugin authors do

1. Insert `dsh-taiwind` alongside your plugin in its `cordis.patch.yml`.
2. Declare the uncompiled CSS entry in `dsh.taiwind` in `package.json`, such as `src/main.css`; the path must stay inside the package.
3. List the entry CSS and the files it references relative to it under `files` so the published package carries them.

```json
{
  "dsh": {
    "taiwind": "src/main.css"
  },
  "files": ["src/main.css"]
}
```

`main.css` keeps CSS-first syntax: `@import "tailwindcss";`, `@theme`, `@utility`, and `@apply` all work. When you need JS configuration, reference it explicitly with `@config "./tailwind.config.js";`.

## Behavior and limits

| Item | Behavior |
| --- | --- |
| Scan scope | Build outputs of every plugin in the current client plugin graph; graph changes trigger a recompile |
| Style merging | Sorted by plugin ID and entry path, then handed to one Tailwind compiler; CSS definitions win over JS, and later duplicates override earlier ones |
| First paint | Uses this round's output or the disk cache; only when neither exists does the official boot overlay appear |
| Failure fallback | A failed compile keeps serving the previous version with a single warning; a failed client fetch keeps the current styles and retries every 2 seconds |
| Unsupported | TypeScript configuration, npm CSS imports, path aliases, remote CSS, `@plugin`, file paths in `@source`, custom scan directories, and cross-package CSS |
| Cost | Requires Tailwind and the Oxide scanner, about 8–10 MB on disk, plus host CPU time |

It targets plugin authors only; users do not install or configure it. Style definitions are shared globally across plugins, so one plugin's invalid configuration blocks that update but does not remove styles already mounted by other plugins.

<Warning>
  A shared stylesheet is not an isolation boundary. Plugins can still execute local code; style conflicts affect appearance only, not plugin permissions.
</Warning>
