`dsh-tauri-model-config` extends the desktop **Settings → Models** page with model parameter controls and automatic configuration.

{/* <!-- [Capacity inputs, image input, and thinking-mode switches on the model settings page](/images/en/dsh-tauri-model-config.png) --> */}

## Features

- Configure context and output limits, image input, and thinking levels.
- Fill in model parameters with **Fetch config** or **Configure all models**.
- Use **Disable Developer role** for compatible endpoints; this option appears only when the route explicitly uses `openai-completions`.
- Use **Open config file** to view and edit the model configuration in an external editor; if the file does not exist, its directory opens instead.

## Automatic configuration

The per-row **Fetch config** action only fills gaps and preserves values you entered. **Configure all models** replaces existing context and output limits with values returned by the endpoint, leaving undisclosed fields unchanged.

Capacity comes from the provider endpoint first. Image input and thinking capabilities use an online capability table, falling back to cached data or model naming rules when offline. Automatic results can be inaccurate; adjust them in advanced settings when needed.

## Data and boundaries

- The plugin replaces the official model settings page and should not be enabled alongside the official entry.
- It requests provider endpoints, downloads and caches capability data, and reads and writes Harness settings. It adds no operating-system sandbox.
- **Open config file** uses `$DSH_HOME/settings.yaml`, or `~/.dsh/settings.yaml` when unset. It does not detect a custom `settings-file` path in a profile.
