title: Third-party kernels (Codex and Claude)
description: Learn where the local Codex and Claude Code kernel entries moved and how to install them now.
---

`dsh-tauri-kernel` moved to the manifest's deprecated list (`plugins.depercated`) and no longer ships with the desktop resources. Local Codex and Claude Code entries now come from the community preset **DSH Third Kernel** (`dsh-third-kernel`).

## Install

1. Select **DSH Third Kernel** in the first-run guide or in **Configuration → Plugins → Open preset**.
2. Install it, restart Harness when prompted, and confirm the plugin loads.
3. Confirm that `codex --version` or `claude --version` works in that computer's terminal, and sign in to the corresponding CLI.

Presets do not count as built-ins, and the manifest's declared core range for that preset decides compatibility. See [plugin management](../guides/plugins) for install and removal steps.

## Sessions and boundaries

- Choosing a kernel creates a new session; it does not switch the current session's kernel.
- A native session's kernel binding cannot change. Model and reasoning changes apply only to the next complete turn.
- These CLIs use their own credentials and services; Harness's DeepSeek model configuration does not replace them.
- They can still execute commands, modify files, and access the network. The plugin and profiles add no OS sandbox.

This page is kept to document the migration; it no longer describes current built-in behavior.
