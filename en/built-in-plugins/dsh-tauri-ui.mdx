---
title: DSH Tauri UI
description: Understand the desktop settings sidebar and its compatibility fallback.
---

`dsh-tauri-ui` provides the desktop settings sidebar, session-entry adaptations, and shared UI components. Harness and plugins still register the settings content; there is no separate settings data model.

## Open settings and return to your session

<Steps>
  <Step title="Open settings">Open the sidebar from the Harness settings entry and use search to filter sections.</Step>
  <Step title="Choose a section">The sidebar renders official and plugin settings through `settings.section`, updating with the language and registered content.</Step>
  <Step title="Return to the app">Closing the sidebar restores the content column and sidebar interactions. Background content and Better Sidebar are not interactive while settings are open.</Step>
</Steps>

The settings entry uses `sidebar.settings`, and the sidebar renders in `shell.overlay`. The desktop host can also open a specific section through a `dsh://settings:open` message.

## Session experience

| Entry | Behavior |
| --- | --- |
| Sidebar New Session and the ungrouped row's `+` | When supported, creates an ungrouped session at the host-resolved `$DSH_HOME/ungrouped`, without a project workspace. |
| Start-page workspace picker | Selects a workspace, or an ungrouped session when supported. |
| Resume button in the composer | Offered when the composer is empty, the session has stopped, and the last turn ended with `aborted`, `error`, or `interrupted`. |
| IM panel | Appears when `dsh-im` provides its client service in the desktop iframe. The duplicate settings entry is hidden and restored if the service goes away. |

## Capability-based fallback

Fallback depends on the renderer, adapters, and services actually available. A core version alone does not guarantee every entry point.

| Missing capability or condition | Behavior |
| --- | --- |
| General `SlotOutlet` unavailable, or a mobile device detected | Does not register the desktop settings sidebar; keeps the official settings dialog. |
| `composer.workspace-less` unavailable | Keeps the official workspace picker and button behavior instead of forcing ungrouped sessions. |
| Ungrouped-directory route unavailable | Warns and uses the core's default working directory without blocking session creation. |
| Shortcut catalog, session events, or IM service unavailable | Omits the corresponding shortcut hints, resume button, or IM panel. |

<Note>
  These are embedded Harness settings, not the native desktop Configuration window. Profile, core, and runtime management remain in the desktop shell. Ungrouped sessions are not file-access sandboxes.
</Note>
