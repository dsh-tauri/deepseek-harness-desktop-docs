## Project positioning

| Project | Desktop stack | Main tradeoff |
| --- | --- | --- |
| This project | Tauri 2 commands and Rust services, with windows rendered by a bundled Electron / Chromium runtime; separate Harness service | First-party desktop additions and multiple cores; community plugins are optional |
| anywhere-labs/dsh-desktop | Electron; the desktop is a DSH/Cordis plugin | Plugin composition, Profile setup, and Agents Anywhere phone control |
| dataelement/dsh-desktop | Electron | Local-first, portable Agent presets, PPT, and a paired phone bridge |
| DeepSeek official desktop | Electron; bundled full Harness Web UI and Host | Official public preview; desktop and core update together, with plugins enabled as needed |

Framework names are not performance rankings. Size, memory, and responsiveness also depend on runtimes and plugins; this page has no common benchmark.

## Management, plugins, and recovery

This project uses the v0.30.3 manifest. The official column uses public preview pages and current desktop source; source version numbers are not treated as installer versions.

| Comparison | This project | anywhere-labs | dataelement | DeepSeek official |
| --- | --- | --- | --- | --- |
| Profiles / runtime | Built-in `desktop` Profile; multiple cores, local `dsh` reuse, CLI registration | Profile wizard/switching; pinned Harness | Preserves Profile data; pinned Harness | Dedicated `desktop` Profile; core follows desktop updates, optional CLI registration |
| Plugin strategy | 13 built-in packages (12 desktop plugins plus a shared styling package); `dshmarket` and others are optional presets | Desktop as a plugin; bundled community market | Harness plugins; third-party plugins installed as needed | Shared Harness plugin manager; Creator mode builds plugins |
| Distinctive management | Plugins, Skills and sources, MCP: `dsh-tauri-extension` | Profile settings and plugin CLI | `.dshpreset` import/export, model providers, PPT | Plugin management, execution traces, and developer tools |
| Worktree / scheduling | Session Git Worktrees; scheduled runs and history | Not confirmed | Not confirmed | Worktrees not confirmed; scheduling requires enabling a plugin, off by default |
| Plugin failure recovery | Identifies implicated plugins and guides removal; release-age rejections offer an authorization retry | Recovery assistant | Diagnostics; non-destructive Safe Mode | Native recovery dialog; disable third-party plugins, back up Profile patch, and restart |

- This project recommends core `0.2.1-rc.5`, minimum `0.2.1-rc.1`; anywhere pins `0.2.1-rc.3` on its channels.
- dataelement currently pins `@deepseek-ai/dsh@0.2.2-alpha.2`, which does not match its README wording. Use the version manifest.
- Built-in IDs here include `dsh-tauri-scheduler`, `dsh-tauri-archive`, `dsh-tauri-model`, and `dsh-tauri-notification`. The local Codex/Claude kernel entry moved to the deprecated list and is now provided by the `dsh-third-kernel` preset.
- Official Desktop and CLI share product data such as sessions and settings, but keep plugin activation and executable dependencies separate; this is not multiple-core switching.

## Different remote-access mechanisms

| Mechanism | This project | anywhere-labs | dataelement | DeepSeek official |
| --- | --- | --- | --- | --- |
| SSH remote host | Built-in `dsh-tauri-remote`; connects to remote `dsh web` through a loopback tunnel | Not confirmed | Not confirmed | Not confirmed |
| Phone continuation | Built-in LAN / Cloudflare tunnel and pairing; browser or DSH Mobile (Android APK / iOS TestFlight) continuation | Agents Anywhere (since 2.0.9) | Separate paired bridge: LAN / temporary internet tunnel | Not confirmed |

- SSH runs Harness on a remote host; phone bridges continue desktop sessions. They are not the same kind of “remote support.”
- anywhere's browser-opening option does not change the bind address; separately enabling LAN exposes an unauthenticated endpoint. Use only fully trusted networks.
- dataelement keeps Harness on a random loopback port; internet pairing needs a password, and disconnecting the phone invalidates its mobile session.

## How to choose

- For multiple cores, first-party panels, Worktrees, scheduling, or SSH hosts, start with this project and check the stable/Nightly distinction.
- For a plugin-composed desktop and Agents Anywhere, consider anywhere; for portable presets, PPT, and paired phone access, consider dataelement.
- To use the official Harness desktop preview directly, check the official download page, confirm your OS and architecture, then enable plugins as needed.

<Warning>
  Harness and plugins can execute local code. Profiles, Worktrees, Safe Mode, and plugin protection are not OS sandboxes.
  Review installers, plugins, and network exposure; use OS-level isolation for untrusted work.
</Warning>
