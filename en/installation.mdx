## Bundled installers (Bundle)

The version selector above lists **Bundle** downloads separately for each release:

| Platform | Bundle installer |
| --- | --- |
| Windows x64 | `Deepseek.Harness.Desktop_Bundle_<version>.exe` |
| macOS Apple Silicon | `Deepseek.Harness.Desktop_Bundle_<version>_aarch64.dmg` |
| macOS Intel | `Deepseek.Harness.Desktop_Bundle_<version>_x64.dmg` |
| Linux x64 (Debian / Ubuntu) | `Deepseek.Harness.Desktop_Bundle_<version>.deb` |

Bundles include runtimes, Harness, and built-in plugins to reduce first-launch downloads. Model access and later updates may still need a network connection. Releases without Bundles do not show this download list.

## Systems and installers

These are the actual release assets and system requirements:

| Platform | Requirements and architecture | Installer |
| --- | --- | --- |
| Windows | Windows 10+; x64 | `.exe` / `_x64_en-US.msi` |
| macOS | macOS 12+; Apple Silicon / Intel | `_aarch64.dmg` / `_x64.dmg` |
| Linux | x64 / ARM64; glibc up to 2.35 (built on Ubuntu 22.04) | `.deb` / `.AppImage` |

The interface renders in the Chromium runtime bundled with the installer, so it does not depend on the system WebView. Available architectures and installer types depend on the selected release's actual assets. Git features such as worktrees also require Git installed on your system.

On macOS, you can also use Homebrew:

```bash
brew install dsh-tauri/desktop/deepseek-harness
```

On Fedora 43+ (x64 / ARM64), install from the Copr repository. Updates then follow `dnf upgrade`, and in-app updates are turned off; switch to `dsh-tauri-beta` for pre-releases (mutually exclusive with `dsh-tauri`):

```bash
sudo dnf copr enable fairyband/dsh-tauri
sudo dnf install dsh-tauri
```

## Install and launch

1. Run the installer; allow file execution first if using AppImage.
2. Open **DeepSeek Harness Desktop** from the application menu.
3. Keep the app open and stay online while completing [First run](./getting-started/first-run).

Model requests, plugin installation, and updates may still need network access.

## Platform issues

<AccordionGroup>
  <Accordion title="Windows security prompt">
    Confirm the installer came from the official Release, then allow it to run. The installer already bundles a Chromium runtime, so WebView2 is not required.
  </Accordion>
  <Accordion title="macOS blocks first launch">
    Verify the download source, then allow the app in **System Settings → Privacy & Security**.
  </Accordion>
  <Accordion title="Window display issues on Linux">
    Prefer `.deb` and confirm the desktop compositor is available. If the window or pet overlay renders incorrectly, enable the XWayland option in pet settings and restart the app. See [Troubleshooting](./help/troubleshooting).
  </Accordion>
</AccordionGroup>
