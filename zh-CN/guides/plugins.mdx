## 本地插件与热重载

除了从 npm 或 GitHub 安装，插件面板还能直接挂载本机的插件源码目录，适合自己开发或正在改动的插件。

1. 在**配置 → 插件**点击安装框右侧的文件夹按钮，选择包含 `package.json` 的插件目录。
2. 面板把该目录回填成 `link:` 开头的绝对路径 spec，先给出只读预检结果，点**安装**后写入活动档案。
3. 安装成功后按提示重启 Harness，让本地插件随档案加载。

安装框也接受手写的 spec：`link:` 或 `file:` 前缀、盘符绝对路径、UNC 路径，以及 `./`、`../` 相对路径都按本地目录处理；相对路径以托管 `dsh` 的安装目录为基准。多个 spec 用逗号或空白分隔可一次安装。

<Note>
  本地目录安装写进档案的是 `link:` 声明，插件源码仍留在原位置。移动或删除该目录会让插件在下次启动时加载失败。
</Note>

热重载默认开启。桌面端在启动 Harness 前把已挂载的本地插件源码目录折算成一组监听目录，写进应用数据中的 `cordis.hmr.patch.yml`，再以 `--patch` 注入核心自带的 HMR 插件；源码改动后由核心卸载并重新加载该插件，无需重启服务。

- 只监听通过本地路径安装的插件，npm 或 GitHub 安装的插件不在其中。
- 改动开关后需要重启服务，才会重新计算监听目录。
- 没有已挂载的本地插件目录时面板会提示，且不写入补丁层。
- `node_modules`、隐藏目录，以及 `cache`、`data` 目录不会被监听。

<Warning>
  热重载执行的是磁盘上的源码。挂载来路不明的目录等同于运行其中的代码。
</Warning>

## 安装、更新与恢复

1. 打开桌面**配置 → 插件**，确认活动档案、来源、版本和错误信息。
2. 安装可信插件，或升级、移除不再需要的可选插件。
3. 按提示重启 Harness，确认插件加载成功。
4. 操作中断时使用面板显示的恢复入口；内置插件缺失时由桌面端修复。

推荐 Harness `0.2.1-rc.5`，最低接受 `0.2.1-rc.1`；实际可选内核和插件版本仍受兼容规则限制。pnpm 默认不解析发布不足 24 小时的新版本，被发布保护期拦下的升级会在面板中给出授权入口。启动异常先保留日志，再使用明确的恢复入口，见[故障排除](../help/troubleshooting)。

<Warning>
  安装插件就是安装可执行的本地代码。Profile 不提供操作系统级沙箱；不要把“内置”“推荐”或“开源”当作无风险保证。
</Warning>

开发者可阅读[插件系统架构](../architecture/plugin-system)。
