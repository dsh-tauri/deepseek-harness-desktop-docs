`dsh-taiwind` 是清单 `plugins.built-in` 中的一个共享样式插件：它在宿主侧收集各客户端插件用到的 Tailwind 工具类，统一编译成一份样式注入页面。它没有界面和工具，唯一产物是共享样式接口 `plugins/taiwind.css` 与页面上的 `<style data-plugin="dsh-taiwind">`。

## 为什么随桌面分发

- 插件各自发布时，同一个 `flex`、`gap-2`、`w-full` 会在同一页面被编译并加载多次。
- 把编译放进宿主进程后，插件仍可独立发布与构建，不必进同一个 monorepo，也不必各自处理去重。
- 桌面端的内置插件与可选预设都依赖这份共享样式，所以它随安装包分发，而不是留给用户单独安装。

## 插件作者需要做什么

1. 在业务插件的 `cordis.patch.yml` 中随行插入 `dsh-taiwind`。
2. 在插件 `package.json` 的 `dsh.taiwind` 字段声明未编译的 CSS 入口，例如 `src/main.css`；该路径必须位于包内。
3. 把入口 CSS 与它相对引用的文件写进 `files`，保证发布产物带上它们。

```json
{
  "dsh": {
    "taiwind": "src/main.css"
  },
  "files": ["src/main.css"]
}
```

`main.css` 保留 CSS-first 写法：`@import "tailwindcss";`、`@theme`、`@utility`、`@apply` 都可以直接用。需要 JS 配置时在 CSS 内显式写 `@config "./tailwind.config.js";`。

## 行为与限制

| 项目 | 行为 |
| --- | --- |
| 扫描范围 | 当前客户端插件图里所有插件的构建产物；插件图变化会自动触发重新编译 |
| 样式合并 | 按插件 ID 与入口路径排序后交给同一个 Tailwind 编译器；CSS 定义优先于 JS，同名时后者覆盖 |
| 首屏 | 先用本轮产物或磁盘缓存，两者都没有时才显示官方启动覆盖层 |
| 失败降级 | 编译失败时继续下发上一版并只记一条 warn；客户端取样式失败时保留现状并每 2 秒重试 |
| 不支持的写法 | TypeScript 配置、npm CSS 导入、路径别名、远程 CSS、`@plugin`、把文件路径写进 `@source`、自定义扫描目录、跨包 CSS |
| 开销 | 需要安装 Tailwind 与 Oxide 扫描器，约占 8–10 MB 磁盘，并产生宿主 CPU 开销 |

它只适用于插件作者；普通用户不需要单独安装或配置。样式定义在所有插件间全局共享，一个插件的非法配置会阻止更新，但不会删除其他插件已挂载的样式。

<Warning>
  共享样式不构成隔离边界。插件仍可执行本地代码；样式冲突只影响外观，不影响插件权限。
</Warning>
