DeepSeek Harness Desktop 是 Tauri 2 应用：Rust 负责窗口、命令与系统集成，窗口和界面由安装包内置的 Electron / Chromium 运行时渲染。桌面端管理本地 Harness 服务，并在原生窗口中显示其 Web 界面。

## 架构图

下图展示本地运行路径：桌面 UI 通过 Tauri command 与 Rust 后端交互，后端管理独立的 Harness 服务进程；嵌入客户端通过回环地址访问该服务。

```text
+---------------------------+      +---------------------------+
| Window / Chromium WebView  |      | Native backend            |
| Desktop UI (React)        |<---->| Rust / Tauri 2            |
| Settings, profiles, etc.  | IPC  | Runtime & service manager |
|                           |      +-------------+-------------+
| +-----------------------+ |                    |
| | Embedded Harness UI   | |          launch / stop / health
| | (iframe)              | |                    |
| +-----------+-----------+ |                    v
+-------------|-------------+      +---------------------------+
              +------------------->| Local Harness service     |
                 127.0.0.1:<port>  | Node.js / dsh             |
                                   | Sessions, tools, plugins  |
                                   +-------------+-------------+
                                                 |
                                   +-------------+-------------+
                                   |                           |
                                   v                           v
                          +----------------+          +----------------+
                          | Local data &   |          | Model provider |
                          | workspace      |          | APIs           |
                          +----------------+          +----------------+
```

图中的 IPC 表示桌面 UI 与原生后端的命令及事件交互；本地数据包含档案与会话数据。组件边界不等于安全沙箱，工具与插件仍可能执行本地代码。

## 主要层次

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面 UI | React 19、TypeScript、Vite、Tailwind CSS 4 | 设置、Profile、插件、更新与窗口状态 |
| 窗口运行时 | Electron（Chromium）与 `tauri-runtime-electron` | 承载桌面窗口与 WebView，由 Rust 侧驱动事件循环、命令与 ACL |
| 原生后端 | Rust 与 Tauri 2 | 运行时发现、下载、服务生命周期、文件、CLI 与系统 API |
| Harness 服务 | 托管或兼容的本地 `dsh` 内核 | 会话、工具、Profile、插件与本地 Web 应用 |
| 嵌入客户端 | 回环 URL 上的 Harness Web UI | 桌面窗口内的主要会话体验 |

## 启动流程

<Steps>
  <Step title="解析配置">Rust 确定正式版或 Debug 路径、活动 Profile、首选内核与端口。</Step>
  <Step title="准备依赖">复用兼容的本地工具或准备托管 Node.js、pnpm 与内核；首次启动需要联网下载缺少的依赖。</Step>
  <Step title="确保插件">启动服务前检查并恢复活动 Profile 的内置插件。</Step>
  <Step title="启动并探测 Harness">选定 Node 启动 Harness 入口，传入 `--profile <id> --port <port> --no-open`，然后等待健康检查。</Step>
  <Step title="加载客户端">窗口从设置或加载状态切换到本地 Harness UI；默认端口为正式版 `3080`、Debug `3081`，占用时可避让。</Step>
</Steps>

## 信任边界

Web 客户端、Rust 后端、Harness 进程、插件、模型供应商和工作区是不同组件，但并非独立安全沙箱。
Tauri command 缩小原生能力范围；Harness 工具和插件仍可使用用户权限执行本地代码，Profile 不是操作系统沙箱。
Chromium 的进程沙箱只隔离渲染进程，不限制插件与 Harness 进程持有的用户权限。
